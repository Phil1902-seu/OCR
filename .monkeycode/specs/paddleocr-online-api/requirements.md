# 需求文档

## 介绍

基于 Android 原生技术栈（Kotlin + Jetpack Compose）开发的在线 OCR 图片文字识别应用。通过调用百度智能云 OCR API（基于 PaddleOCR 技术）实现文字识别，替代原有 RapidOCR 本地 ONNX 推理方案。应用支持拍照或选图后上传至云端进行识别，支持中英文混合识别，识别结果可编辑、复制和分享。

本次重构将 OCR 推理引擎从本地 ONNX Runtime 迁移至百度智能云在线 API，移除 JNI/C++ 原生层，改为纯 Kotlin HTTP 网络调用，大幅减小 APK 体积，降低构建复杂度。

## 术语表

- **OCR**: 光学字符识别（Optical Character Recognition），将图片中的文字转换为可编辑文本
- **PaddleOCR**: 百度飞桨开源的 OCR 技术框架，提供高精度多语种文字识别能力
- **百度智能云 OCR API**: 百度智能云提供的在线文字识别服务，底层基于 PaddleOCR 技术，通过 HTTP 接口提供识别能力
- **access_token**: 百度智能云 API 的访问令牌，通过 API Key + Secret Key 换取，有效期 30 天
- **API Key / Secret Key**: 百度智能云应用的凭证对，用于换取 access_token
- **通用文字识别（高精度版）**: 百度智能云提供的 OCR 接口，识别精度更高，端点为 `accurate_basic`
- **通用文字识别（标准版）**: 百度智能云提供的 OCR 接口，识别速度更快，端点为 `general_basic`
- **文本检测**: 定位图片中文字所在区域
- **文本识别**: 将检测到的文字区域转换为实际文本内容

## 需求

### 需求 1: 相机拍照识别

**用户故事:** 作为用户，我想要通过相机拍摄图片并识别其中的文字，以便于快速提取现实场景中的文字内容。

#### 验收标准

1. WHEN 用户点击拍照识别按钮，系统 SHALL 启动系统相机进行拍摄
2. WHEN 用户完成拍摄确认照片，系统 SHALL 将照片上传至百度智能云 OCR API 进行识别
3. WHILE OCR 识别正在进行，系统 SHALL 显示加载指示器并提示"正在识别..."
4. IF 网络不可用，系统 SHALL 提示用户"网络不可用，请检查网络连接"
5. IF OCR API 调用失败，系统 SHALL 提示用户"识别失败，请重试"

### 需求 2: 相册选图识别

**用户故事:** 作为用户，我想要从相册选择已有图片进行文字识别，以便于识别已有照片中的文字。

#### 验收标准

1. WHEN 用户点击相册选图按钮，系统 SHALL 打开系统相册选择器
2. WHEN 用户选择一张图片，系统 SHALL 将图片上传至百度智能云 OCR API 进行识别
3. IF 图片格式不支持，系统 SHALL 提示用户"不支持的图片格式"
4. IF 图片尺寸超过 4096x4096 像素，系统 SHALL 自动压缩后再上传识别

### 需求 3: OCR 识别结果展示

**用户故事:** 作为用户，我想要看到 OCR 识别的结果，包括文字内容和每个文字区域的位置信息，以便于核对和使用识别结果。

#### 验收标准

1. WHEN OCR 识别完成，系统 SHALL 显示识别出的全部文字内容（按行排列）
2. WHEN OCR 识别完成且 API 返回位置信息，系统 SHALL 在原始图片上以方框标注检测到的文字区域
3. WHEN 用户点击某个文字区域标注，系统 SHALL 高亮显示对应的文字内容
4. IF 未检测到任何文字，系统 SHALL 显示"未检测到文字内容"

### 需求 4: 识别结果编辑与操作

**用户故事:** 作为用户，我想要对识别结果进行编辑、复制和分享，以便于使用识别出的文字。

#### 验收标准

1. WHEN 用户点击编辑按钮，系统 SHALL 进入编辑模式，允许用户修改识别文字
2. WHEN 用户点击复制按钮，系统 SHALL 将识别文字复制到系统剪贴板
3. WHEN 用户点击分享按钮，系统 SHALL 调起系统分享面板分享识别文字
4. IF 复制成功，系统 SHALL 显示"已复制到剪贴板"提示

### 需求 5: API 凭证管理

**用户故事:** 作为用户，我想要在应用内配置百度智能云 API 凭证，以便于应用能够调用在线 OCR 服务。

#### 验收标准

1. WHEN 应用首次启动且未配置 API 凭证，系统 SHALL 引导用户进入设置页面填写 API Key 和 Secret Key
2. WHEN 用户在设置页面输入 API Key 和 Secret Key 并保存，系统 SHALL 使用凭证换取 access_token 并缓存
3. WHEN 已缓存的 access_token 过期，系统 SHALL 自动使用缓存的 API Key 和 Secret Key 重新换取 access_token
4. IF access_token 换取失败（凭证无效），系统 SHALL 提示用户"API 凭证无效，请检查后重新配置"
5. 系统 SHALL 将 API Key 和 Secret Key 加密存储在应用私有空间，禁止以明文形式存储
6. 系统 SHALL 在设置页面提供"测试连接"功能，验证当前凭证是否可用

### 需求 6: 识别模式切换

**用户故事:** 作为用户，我想要在标准精度和高精度两种识别模式之间切换，以便于在速度和精度之间取得平衡。

#### 验收标准

1. 系统 SHALL 在设置页面提供"识别模式"选项，允许用户在"标准模式"和"高精度模式"之间切换
2. WHEN 用户选择"标准模式"，系统 SHALL 调用 `general_basic` 接口进行识别
3. WHEN 用户选择"高精度模式"，系统 SHALL 调用 `accurate_basic` 接口进行识别
4. WHEN 用户选择"高精度含位置"模式，系统 SHALL 调用 `accurate` 接口进行识别并返回文字位置信息
5. 系统 SHALL 记住用户上次选择的识别模式，下次启动时默认使用上次的设置

### 需求 7: 识别历史记录

**用户故事:** 作为用户，我想要查看之前的识别记录，以便于回顾和使用历史识别结果。

#### 验收标准

1. WHEN 每次 OCR 识别完成，系统 SHALL 保存识别记录（缩略图 + 文字摘要 + 时间戳 + 识别模式）
2. WHEN 用户打开历史记录页面，系统 SHALL 按时间倒序展示历史记录列表
3. WHEN 用户点击某条历史记录，系统 SHALL 展示完整的识别结果详情
4. IF 用户清空历史记录，系统 SHALL 弹出二次确认对话框

### 需求 8: 识别结果导出

**用户故事:** 作为用户，我想要将识别结果导出为多种格式（TXT / PDF / Markdown / JSON），以便于归档和在其他软件中解析使用识别结果。

#### 验收标准

1. WHEN 用户点击导出按钮，系统 SHALL 弹出格式选择面板（TXT / PDF / Markdown / JSON）
2. WHEN 用户选择 TXT 格式，系统 SHALL 将识别文字按行导出为纯文本文件
3. WHEN 用户选择 PDF 格式，系统 SHALL 将识别文字和原图导出为 PDF 文件
4. WHEN 用户选择 Markdown 格式，系统 SHALL 将识别文字以 Markdown 结构化格式导出，包含原图引用和文字块
5. WHEN 用户选择 JSON 格式，系统 SHALL 将识别结果以结构化 JSON 导出，包含每个文字区域的文本、坐标、置信度和图片元信息
6. 系统 SHALL 将导出文件保存到用户指定的存储位置
7. IF 导出成功，系统 SHALL 显示"导出成功"提示并提供快捷打开入口

## 非功能性需求

### 性能

- 单次 OCR 识别总耗时（含网络传输 + 服务端识别）SHALL 不超过 5 秒（良好网络环境下）
- 应用冷启动时间 SHALL 不超过 2 秒
- 图片上传前 SHALL 进行压缩处理，单张图片传输大小 SHALL 不超过 4MB（百度 API 限制）

### 兼容性

- 最低支持 Android 8.0 (API 26)
- 目标 Android 14 (API 34)

### 易用性

- 遵循 Material Design 3 设计规范

### 安全性

- API 凭证 SHALL 使用 Android Keystore 进行加密存储
- 网络 SHALL 全部使用 HTTPS 传输
- 图片上传 SHALL 仅包含必要的图片数据，禁止携带用户隐私元信息（如 GPS 位置等 EXIF 数据）
